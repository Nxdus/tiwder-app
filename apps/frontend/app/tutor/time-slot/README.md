# Tutor time slot

หน้านัดเวลาเรียนฝั่งผู้สอน ใช้ Next.js App Router, TypeScript, Tailwind และ shadcn/ui เดิมของโปรเจกต์

## แบบ Figma

- ลิงก์ที่ได้รับ (`15:121`) เป็นหน้า Swiped-Tutor
- หน้าที่นำมาทำจริงคือ [Swiped time slot-Tutor — ก่อนเลือกเวลา](https://www.figma.com/design/jDGcDvkt4vOq8LKIVsmIHB/Web-Pro?node-id=15-423) และ [หลังเลือกเวลา](https://www.figma.com/design/jDGcDvkt4vOq8LKIVsmIHB/Web-Pro?node-id=49-114) ในไฟล์เดียวกัน
- ใช้โครงหน้าจาก Figma ร่วมกับธีมหน้า Swiped: Inter, พื้น `bg-primary/5`, สีจาก theme tokens และสไตล์ shadcn ของโปรเจกต์ การ์ดกว้าง 330px ปฏิทินกว้าง 337px และระยะระหว่างสองคอลัมน์ 32px
- หน้าจอเล็กกว่า `md` เรียงข้อมูลนักเรียนและปฏิทินเป็นแนวตั้ง

## เปิดตรวจ

รัน `bun run dev` จาก `apps/frontend` แล้วเปิด `http://localhost:3000/tutor`

- `/tutor` เปลี่ยนเส้นทางมาที่ `/tutor/time-slot`
- `/tutor/time-slot` แสดงนักเรียนตัวอย่างคนแรก
- `/tutor/swiped` คลิกที่รูปนักเรียนเพื่อเปิด `/tutor/time-slot?student=demo-student-3` เป็นต้น
- รหัสนักเรียนที่ไม่มีในข้อมูลตัวอย่างแสดงหน้า 404

## การทำงานและข้อจำกัด

- เลือกวันที่และเวลาได้จริง โดยเวลาเริ่มและสิ้นสุดต้องอยู่ในวันเดียวกัน และเวลาสิ้นสุดต้องมากกว่าเวลาเริ่ม
- ปฏิทินเริ่มที่วันและเดือนปัจจุบันตามเขตเวลา Asia/Bangkok โดยคำนวณฝั่งเซิร์ฟเวอร์เมื่อมี request และส่งค่าเดียวกันให้ client ป้องกันวันเริ่มต้นต่างกันตอน hydration
- เลือกเดือนและวันได้ มีปุ่มเดือนก่อนหน้า/ถัดไป ปีแสดงเป็นข้อความ ไม่มี dropdown เลือกปี และยังไม่ได้ใช้ข้อมูลเวลาว่างจริง
- Time Start และ Time End มีปุ่มเดียวต่อฝั่ง แสดงเวลาและ AM/PM รวมกัน เมื่อกดเปิด shadcn Popover ตรงกลางกรอบร่วมกัน ภายในเลือกเวลาและ AM/PM แยกกันด้วย Button ปิดแผงได้ด้วยการกดด้านนอกหรือ Escape
- คำว่า Time และตัวเลือกเวลาใช้พื้นที่เนื้อหาเดียวกันเพื่อจัดกึ่งกลางตรงกัน วาง scrollbar ที่ขอบซ้าย และตรึงหัวข้อไว้เมื่อเลื่อนรายการ โดยลำดับข้อความเวลายังคงอ่านจากซ้ายไปขวา
- ข้อความ `Please select a date and time.` เป็นสีแดงพร้อมพื้นและขอบ อยู่ใต้ช่องเลือกเวลาโดยตรงจนกว่าจะเลือกครบ หากช่วงเวลาไม่ถูกต้องจะแสดงข้อผิดพลาดในตำแหน่งเดียวกัน
- เมื่อเลือกครบ จะแสดงสรุปและราคาตัวอย่างที่คำนวณในอัตรา 250 บาทต่อชั่วโมง ยังไม่ใช่ราคาจาก API
- Confirm Time บันทึกการกันเวลาใน IndexedDB ของเบราว์เซอร์ (`tiwder-tutor-demo`) เปลี่ยนนักเรียนหรือรีเฟรชแล้วนัดยังอยู่ แต่ค่าที่กำลังเลือกในฟอร์มจะเริ่มใหม่ ยังไม่มีการส่งนัดไป backend หรือรับการยืนยันจาก student
- ติวเตอร์ตัวอย่างคนเดียวใช้ตารางเวลาร่วมกันสำหรับนักเรียนทุกคน เมื่อจองวันที่ 6 พ.ย. 2026 เวลา 12:00–13:00 แล้ว ห้ามจองซ้ำหรือทับบางส่วน เช่น 12:30–13:30 แต่ 11:00–12:00 และ 13:00–14:00 จองได้ รวมถึงเวลาเดียวกันในวันอื่น
- แสดงเวลาที่ถูกจองของวันที่เลือก และปิดตัวเลือกเวลาหรือปุ่มยืนยันที่ทับนัดเดิม รวมทั้งเวลาจากรายการ Matched ตัวอย่าง ข้อมูล Matched ตัวอย่างถูกจัดให้ต่อกันโดยไม่ซ้อนกัน
- ก่อนบันทึกจะอ่านนัดล่าสุดและตรวจซ้ำภายใน IndexedDB readwrite transaction จึงกันการยืนยันเวลาซ้อนจากหลายแท็บพร้อมกันได้ ใช้ BroadcastChannel และการกลับมาโฟกัสแท็บเพื่อรีเฟรชรายการเวลาที่ถูกจอง หากอ่านข้อมูลเบราว์เซอร์ไม่ได้จะไม่เปิดให้ยืนยัน
- ข้อมูลนี้แยกตามเบราว์เซอร์ โปรไฟล์ และ origin เช่น `localhost:3000` กับ `127.0.0.1:3000` เป็นคนละชุด ไม่กันเวลาร่วมกันข้ามเครื่อง และจะหายเมื่อล้างข้อมูลเว็บไซต์ หากใช้งานจริงต้องให้ backend และฐานข้อมูลบังคับกติกาอีกชั้น
- เปลี่ยนนักเรียนแล้วเริ่มการเลือกเวลาใหม่ด้วย `key` ของนักเรียน เพื่อไม่ให้เวลาของอีกคนติดมาด้วย
- ลิงก์ Swiped และ Matched ใช้งานได้ โดย Matched เปิด `/tutor/matched` ส่วนโปรไฟล์ยังปิดไว้เพราะปลายทางยังไม่พร้อม
- โทรศัพท์และอีเมลเป็นลิงก์ `tel:`/`mailto:` จริง แต่ข้อมูลเป็นตัวอย่าง
- ใช้รูปนักเรียน ข้อความ สี Badge และ Separator เดียวกับหน้า Swiped ผ่านคอมโพเนนต์ร่วมกัน รูป placeholder ใช้เมื่อนักเรียนไม่มีรูป
- Calendar, Popover และ Button ใช้สไตล์ shadcn เดิม วันที่เลือกและปุ่ม Confirm Time ใช้สี primary ของโปรเจกต์ ปุ่มวันลดเหลือ 32px และจัดกลางเซลล์เพื่อให้วงวันที่เลือกกับ hover มีระยะห่าง

## ผลตรวจ

- ESLint และ TypeScript ผ่าน
- `node --experimental-strip-types --test app/tutor/time-slot/schedule.test.mjs app/tutor/time-slot/bookings.test.mjs app/tutor/matched/matches.test.mjs` ผ่าน 11 รายการ
- ทดสอบในเบราว์เซอร์จริง: ให้นักเรียน 2 คนกดยืนยันวันที่ 6 พ.ย. 2026 เวลา 12:00–13:00 พร้อมกันจากสองแท็บ ได้เพียง 1 นัด อีกแท็บถูกปฏิเสธ ตัวเลือกเวลา 12:00 และ 12:30 PM ถูกปิด แต่จองต่อ 13:00–14:00 ได้ และทั้งสองนัดยังปรากฏหลังรีเฟรช
- เปิดทดสอบที่ความกว้าง 1440, 375 และ 320px ไม่มีส่วนล้นแนวนอน ตรวจเลือกวัน เลือกเวลา ช่วงเวลาผิด การยืนยันตัวอย่าง และลิงก์จาก Swiped แล้ว
- แก้ปัญหา hydration ของวันที่ด้วย locale `enUS` ที่ระบุชัดทั้ง Calendar และปุ่มวัน
- วัด Header และ navigation ที่ขนาดเดียวกันทั้งสองหน้าแล้ว ตำแหน่งตรงกันหลังจองพื้นที่ scrollbar ทดสอบเปลี่ยนไปกุมภาพันธ์ 2028 เลือกวันที่ 29 และช่วง 11:30 AM ถึง 12:30 PM ได้
- Production build ผ่านแล้วในการตรวจวันที่ 5 พฤศจิกายน 2026 ทั้งการ build จาก cache ใหม่และคำสั่ง `bun run build` โดยใช้ Turbopack และ config เดิม ข้อผิดพลาด CSS worker ที่เคยพบไม่เกิดซ้ำในการตรวจล่าสุด แต่ยังไม่ยืนยันต้นเหตุเดิม จึงไม่มีการเปลี่ยน config หรือ dependencies เพื่อหลบปัญหา

ควรตรวจด้วยตาว่าหน้าทั้งสองสถานะตรงกับแบบที่ต้องการ และยืนยันกติกาวันนัด ราคา และ API ก่อนใช้งานจริง
